# ADR-007: 正方教务接口契约（已由真实抓包确认）

## 状态

已接受

## 背景

课表数据不在办事大厅，而在**正方教务系统**（`jwxt.gzus.edu.cn/jwglxt`）。
用户通过办事大厅「应用中心 → 教学综合信息服务平台学生入口 → 我要办理 → 我已知晓」
跳转进入，并抓到了完整的课表接口与响应。

## 已确认的接口契约

### 课表数据接口

```
GET https://jwxt.gzus.edu.cn/jwglxt/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151
```

| 相关接口 | 作用 |
|---|---|
| `xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 查询页面外壳 |
| `xskbcx_cxXskbcxIndex.html?gnmkdm=N2151` (xhr) | 学年/学期下拉选项 |
| **`xskbcx_cxXsKb.html?gnmkdm=N2151` (xhr)** | **课表数据本体** |
| `xskbcx_cxRsd.html` / `cxRjc.html` | 时间段 / 节次元数据 |

### 响应结构

```json
{
  "xsxx": { "XH": "学号", "XM": "姓名", "XNMC": "2026-2027", "XQMMC": "1", "BJMC": "班级" },
  "xqjmcMap": { "1": "星期一", ..., "7": "星期日" },
  "kbList": [ { ...单节课... } ]
}
```

### 单节课字段映射

| 业务含义 | 正方字段 | 示例 | 备注 |
|---|---|---|---|
| 课程名称 | `kcmc` | `数据库原理` | |
| 星期几 | `xqj` | `2` | 1-7；`xqjmc` 为中文 |
| 节次 | `jcor` / `jcs` | `3-4` | ⚠️ 优先 `jcor`（纯数字）；`jc` 带"节"字 |
| 周次 | `zcd` | `1-18周` | ⚠️ **含单双周** |
| 教室 | `cdmc` | `A101` | `lh` 是楼栋名（教学楼/实验楼） |
| 教师 | `xm` | `张老师` | |
| 学分 | `xf` | `3.0` | |
| 课程性质 | `kcxz` / `kclbmc` | `必修` | |
| 校区 | `xqmc` | `示例校区` | |
| 教学班 | `jxbmc` / `jxbzc` | `(2026-2027-1)-ME2006-2` | |
| 是否调课 | `jxbsftkbj` | `0`/`1` | |

### ⚠️ 三个必须处理的坑（均由真实数据发现）

**1. 周次含单双周** —— `zcd` 有三种形态：
```
"1-18周"        → 每周   parity=0
"1-17周(单)"     → 单周   parity=1
"2-18周(双)"     → 双周   parity=2
```
未处理会导致单双周课程**每周都显示**。

**2. 节次有两个字段**：`jcor`（`"3-4"`）与 `jc`（`"3-4节"`）。
用 `jcor` 更省事，但代码同时容忍带单位输入。

**3. 同一门课一周可有多条记录** —— 例如「数据库原理」在
星期二 3-4 节（理论）、星期三 7-8 节、星期四 9-10 节各一条。
**这是正常排课，绝不可按课程名去重**，否则会丢课。

**4. 会话失效时返回 HTML 而非 JSON** —— 解析器必须捕获
`JsonSyntaxException`，否则 App 崩溃。

## 决策

- 解析器置于 `data/sync/zhengfang/ZfScheduleParser.kt`，**纯函数、不依赖 Android**，可单元测试
- 真实响应裁剪后存为 fixture：`app/src/test/resources/zhengfang_schedule_sample.json`
- 测试断言**基于真实数据**（含单双周、多时段等边界），而非构造的理想输入

## 影响

**变容易：**
- 课表解析有 23 个单元测试保驾护航，且全部基于真实数据
- 单双周/多时段等边界已被测试覆盖
- 解析失败不会崩溃（返回空结果）
