# ADR-005: 凭据策略 —— 纯内存、用完即弃

## 状态

已接受

## 背景

App 需要用户账密才能从教务系统拉取数据。但**长期持有凭据或会话存在风险**：

- 密码落盘 → 手机丢失/被 root 即泄露
- 会话长期挂载 → 对学校系统持续压力，且会话过期处理复杂
- 用户明确要求：「账号只是拉取数据用，用完自动退出，下次要更新再自动输入账密拉取」

## 决策

**凭据只存在于内存，登录 → 拉数据 → 立即登出。绝不持久化。**

```
用户输入账密（内存）
      ↓
调用 CAS 登录，拿会话
      ↓
用会话拉取 课表/成绩/考试
      ↓
写入本地 Room 数据库
      ↓
【立即丢弃】会话与密码（内存清空 + 主动登出请求）
```

**下次打开 App**：读本地数据库 → 显示数据 → 需要更新时再让用户输入一次账密。

## 具体约束

| 项 | 规则 |
|---|---|
| 密码 | **绝不写入** SharedPreferences / 数据库 / 文件 / 日志 |
| 会话 Cookie | 仅内存持有；用完置空引用，**不写入磁盘** |
| 学号 | **也不记住**（方案 A，用户选择） |
| 登录后动作 | 拉完数据立刻调用登出接口（`/lyuapServer/auth/logout` 或 `/uniLogout`） |
| 崩溃/异常 | 内存中的凭据随进程销毁，无需额外清理 |
| 日志 | 诊断面板只记录字段名、长度、响应码；**从不记录凭据值** |
| 截屏 | 登录页设 `FLAG_SECURE`，防止密码被截屏/录屏 |

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 纯内存，用完即弃** | 安全性最高；无需处理会话过期；对学校系统压力最小 | 每次更新需重输账密+验证码 | ✅ **用户选定** |
| B. 记住学号（不记密码） | 省一步输入 | 仍需每次输密码+验证码 | ❌ 用户未选 |
| C. 加密存密码（EncryptedSharedPreferences） | 一次输入长期自动更新 | 设备被控时仍可能被提取；责任风险 | ❌ 用户未选 |

**用户明确选择 A**，理由是「账号只是拉取数据用」——即 App 的定位是**离线数据查看器**，不是常驻在线客户端。

## 影响

**变容易：**
- 不需要 EncryptedSharedPreferences、不需要 token 刷新逻辑
- 不需要处理「会话过期 → 静默续期」的复杂状态机
- 安全性天然达标，面试/课设答辩时是加分项

**变难 / 需注意：**
- **UI 必须做空状态**：无本地数据时要有明确引导（→ 「我的」里登录）
- **登录页要能承受重复使用**：每次更新都走一遍，表单体验要顺
- **必须有「上次更新时间」显示**：用户需知道数据有多旧
- **数据新鲜度提示**：过期数据要标注，避免用户误以为是实时

## 连带决策（同批确定）

1. **启动入口 = MainActivity**（不是登录页）。打开先看数据。
2. **登录入口 = 「我的」菜单内**。不主动弹登录。
3. **无数据时**：显示空状态 + 「去同步」按钮（跳转「我的」），不自动跳登录页。
4. **核心功能范围**：课表、成绩、考试、本地缓存。
